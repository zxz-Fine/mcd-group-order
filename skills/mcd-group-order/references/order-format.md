# 报单文本格式与解析规则

`parse_orders.py` 负责把群聊里的报单文本转成结构化 JSON。本文档说明它认哪些写法、不认哪些写法。

## 支持的写法

| 写法 | 示例 | 解析结果 |
|---|---|---|
| `@昵称` 前缀 | `@张三 麦辣鸡腿堡套餐 x1` | 人=张三，餐品=麦辣鸡腿堡套餐 ×1 |
| `昵称：` 前缀 | `李四：巨无霸 + 中薯 + 可乐` | 人=李四，3 个餐品 |
| `昵称 ` 空格前缀 | `王五 2个麦香鱼 1份薯条` | 人=王五，2 个餐品 |
| 中文数量 | `两个麦香鱼` | 麦香鱼 ×2 |
| 后缀数量 | `巨无霸x2` / `巨无霸×2` / `巨无霸*2` | 巨无霸 ×2 |
| 前缀数量 | `2份薯条` / `2杯可乐` | 薯条 ×2 / 可乐 ×2 |
| 备注 | `板烧鸡腿堡 去冰可乐` | 板烧鸡腿堡 + 可乐（备注：去冰） |
| 括号时间戳 | `【12:30】@张三 双层吉士汉堡×2` | 自动剔除时间戳 |
| 独立数量标记 | `麦辣鸡腿堡套餐 x1` | `x1` 回填给前一项，不会当成餐品 |
| 保护 `1+1` | `我 1+1随心配` | 餐品=1+1随心配（数字间的 `+` 不切分） |

## 分隔符

餐品之间可用：空格、`、`、`,`、`，`、`/`、`+`（数字之间的 `+` 除外）。

## 数量识别

- 后缀：`x2` `X2` `×2` `*2` `2个` `2份` `2杯` `2盒` `2套` `2块` `2只` `2支` `2袋` `2瓶`
- 前缀：同上单位
- 中文数字：`一` `两` `二` `三` … `十`

## 备注识别（受控词表）

备注关键词：`不要X`、`去X`/`去掉X`、`少X`、`加X`/`多X`、`换X`、`备注X`。

其中 `X` 取自受控词表：

```
番茄酱 酸黄瓜 沙拉酱 生菜 洋葱 香菜 吸管 餐具 芝士
冰 糖 酱 菜 葱 盐 辣 奶 油 皮 盖
```

**为什么用受控词表？** 两个真实踩过的坑：

1. 若把裸「无」当备注关键词，`巨无霸` 会被拆成 `巨` + 备注 `无霸`。
2. 若用泛化的 `去[^\s]{1,3}`，`去冰可乐` 会被整串吞成备注，丢掉了「可乐」这个餐品。

## 已知边界（交给 LLM 兜底）

脚本是**确定性兜底**，不是主解析器。以下情况请由 LLM 判断，或直接问用户：

- 一句话里混了多人的报单（如 `张三李四都要巨无霸`）
- 「和昨天一样」「老规矩」「加一个那个」这类指代
- 品牌别名与门店黑话（脚本内置了一小张别名表，可在 `match_menu.py` 的 `ALIASES` 里扩展）
- 一个片段里同时含餐品与规格（如 `大杯可乐去冰少糖`）

## 输出结构

```json
{
  "people": ["张三", "李四"],
  "count": 2,
  "item_count": 4,
  "orders": [
    {
      "person": "张三",
      "items": [{ "name": "麦辣鸡腿堡套餐", "qty": 1, "note": "" }],
      "raw_lines": ["@张三 麦辣鸡腿堡套餐 x1"]
    }
  ],
  "warnings": []
}
```

`person` 为 `__ME__` 表示文本里写的是「我」，需替换为实际姓名。
